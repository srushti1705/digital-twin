# Interactive What-If Climate Scenario Engine

## 1. Overview

The What-If Scenario Engine enables policy planners, climate researchers, and students to simulate localized or nationwide hypothetical atmospheric perturbations on top of historical observations or AI predictive baselines.

---

## 2. Mathematical Formulation

### A. Rainfall Perturbation
Rainfall adjustments are applied multiplicatively to reflect percentage-based amplification or deficit in monsoonal activity:

$$R_{\text{scenario}}(i, j) = \max\left(0.0, \, R_{\text{baseline}}(i, j) \times \left(1 + \frac{\Delta R_{\%}}{100}\right)\right)$$

* **Clamping Rule**: Negative rainfall is physically impossible. Grid cells are clamped to a strict lower bound of $0.0\,\text{mm}$.
* **NaN Preservation**: Non-land or oceanic cells outside India's meteorological boundaries evaluate to `NaN` and are strictly excluded from mathematical perturbations and summary statistics.

### B. Temperature Perturbation
Maximum ($T_{\max}$) and minimum ($T_{\min}$) surface temperatures are adjusted additively in degrees Celsius:

$$T_{\max, \text{scenario}}(i, j) = T_{\max, \text{baseline}}(i, j) + \Delta T_{\max}$$
$$T_{\min, \text{scenario}}(i, j) = T_{\min, \text{baseline}}(i, j) + \Delta T_{\min}$$

### C. Physical Consistency & Inversion Check
In the terrestrial troposphere under normal diurnality, maximum daytime temperature must equal or exceed nighttime minimum temperature:

$$T_{\max, \text{scenario}}(i, j) \ge T_{\min, \text{scenario}}(i, j)$$

* **Validation Algorithm**: The scenario engine scans every valid terrestrial grid cell. If any cell violates this constraint ($T_{\min} > T_{\max}$), an explicit `inversion_warning` is raised in the API response:
  > *"Physical Inversion Warning: In X grid cells, Minimum Temperature exceeds Maximum Temperature after perturbation. Review adjustment parameters."*
* The digital twin surfaces this warning with a yellow banner in the frontend UI.

---

## 3. Spatial Masking Engine

Scenarios can be executed at two geographical scopes:
1. **All-India (`all_india`)**: Perturbations apply to all valid land grid cells across the subcontinent.
2. **State-Level (`state:<State_Name>`)**: Perturbations apply exclusively to grid cells falling within the polygon boundaries of the selected Indian State or Union Territory. Unselected regions retain their exact baseline values ($\Delta = 0$).

### Polygon Ray-Casting Implementation
* State boundary geometries are loaded from official `data/shapefiles/geoBoundaries-IND-ADM1.geojson`.
* Vector polygons are converted into `matplotlib.path.Path` instances.
* A coordinate grid of (longitude, latitude) points matching the native grid resolution ($0.25^\circ$ for IMD rainfall, $1.0^\circ$ for IMD temperature) is evaluated using `path.contains_points()`.
* Spatial masks are cached in-memory using an LRU cache (`@lru_cache`) to guarantee sub-millisecond masking performance during repeated runs.

---

## 4. Scientific Disclaimer & Non-GCM Caveats

Every scenario response generated by the backend includes an unambiguous scientific caveat:

> *"Diagnostic Perturbation Model: This scenario is a mathematical perturbation on an empirical or statistical baseline. It does not model coupled dynamic atmospheric feedbacks, moisture convergence, pressure systems, or general circulation physics (GCM). Not intended for operational forecasting."*

## 5. REST API Specification

### 1. `GET /api/scenarios/scopes`
Returns available geographical scopes (All-India and list of all 36 Indian States and Union Territories with bounding boxes).

### 2. `POST /api/scenarios/run`
Executes a scenario simulation.
* **Payload**:
  ```json
  {
    "scenario_name": "Monsoon Deficit + 2C Warming",
    "scope_type": "state",
    "scope_id": "Maharashtra",
    "baseline_source": "observation",
    "baseline_date": "2025-07-15",
    "lead_day": 1,
    "rainfall_change_percent": -25.0,
    "tmax_change_celsius": 2.0,
    "tmin_change_celsius": 1.5,
    "include_grid_data": true
  }
  ```
* **Returns**: `ScenarioResult` with summary metrics (`baseline_mean`, `scenario_mean`, `delta_mean`, `min`, `max`, `std`, `extreme_events_count`), physical inversion warnings, and compact grid arrays.

### 3. `GET /api/scenarios/{scenario_id}`
Retrieves a previously computed scenario from the thread-safe in-memory cache.

### 4. `GET /api/scenarios/{scenario_id}/summary`
Lightweight summary metrics without heavy grid rasters.

### 5. `POST /api/scenarios/compare`
Compares two executed scenarios side-by-side:
* **Payload**: `{"scenario_a_id": "...", "scenario_b_id": "..."}`
* **Returns**: Metric deltas, extreme event differential, and spatial delta summary.

---

## 6. Frontend 3D Globe Visualization

The Cesium globe renders scenario results dynamically via an in-memory 2D Canvas converted to a `SingleTileImageryProvider`:
* **View Layers**:
  * **Scenario Output**: Shows absolute perturbed climate state.
  * **Baseline**: Shows the unperturbed ground truth / prediction.
  * **Difference ($\Delta$)**: Shows a diverging color ramp (e.g. brown-to-cyan for rainfall, blue-to-red for temperature).
* **Inspection**: Clicking any grid cell on the 3D globe inspects baseline value, perturbed value, and delta.
